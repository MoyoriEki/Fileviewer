# Fileviewer (Dropbox Filer)

Dropbox 上の画像・ファイルを閲覧する Web ビュアー（`moyorieki.github.io` 配下・同一オリジンで [プロットボード](https://github.com/MoyoriEki/PlotBuilder) と連携）。単一ファイル `index.html`。

## 変更履歴

- **Phase 6.2（ビューアの操作性改善）**: Android で動画を開いたとき、ビューア上部の ✕ / 🔁 が安定して表示されなかった。原因は、上部バーを動画の上に重ねて表示したうえで 3 秒で自動的に隠しており、再表示のきっかけが画像専用の中央タップとマウス移動しかなかったこと。そのためタッチ端末では一度消えると戻せず、さらに隠れたバーの位置に動画のネイティブコントロール（⋮ など）が重なっていた。画像以外（動画・音声・テキスト・PDF）では `#viewer` に `mode-media` を付け、上下のバーを重ねずにレイアウト内へ固定し、常に表示するようにした（自動非表示もしない）。`<video>` には `playsinline` を付けた。
  下部バーに ‹ › ボタンを追加し、どの種類のファイルでも前後に送れるようにした。これまで画像以外にはタッチ端末から送る手段がなかった。先頭・末尾ではボタンを無効にする。動画の上にタップゾーンやスワイプは付けていない（Android のダブルタップシークやネイティブコントロールと競合するため）。ビューア表示中の ← → は常にページ送りに使い、動画にフォーカスがあってもシークしない。
  あわせて、PC の画像表示でマウスを動かすとバーが再表示される機能を削除した。バーの表示・非表示は端末を問わず中央クリック／タップで切り替える。

- **Phase 6.1（グループの端末間同期の修正）**: グループが別端末の操作で消えることがあった。マージの単位である「フォルダごとの更新時刻」をカスタム順・並びモードと共有していたため、グループをまだ取り込んでいない端末で同じフォルダの並べ替えやソート変更をすると、その端末が新しい側と判定されてグループごと上書きしていた。グループ専用の更新時刻 `groupsUpdatedAt` を設けて独立にマージするようにした。あわせて、グループのメニューや管理画面を開くときはクラウドの最新を先に取り込み、PC で 2 窓を並べている場合に備えてウィンドウの focus でも再同期する。再同期で並べ直したときに選択がずれないようにした。
  なお更新前のコードが残ったタブは設定保存時に `folderGroups` を落とすが、新しいコード側がフォルダ単位の時刻で勝つので次の同期で復元される。古いタブは一度再読み込みするのが確実。

- **Phase 6（グループ機能・仮実装）**: フォルダごとにグループ（名前 + パステル色）を作り、ファイルを振り分けられるようにした。グループ管理はツールバーの 🏷 か余白の右クリックメニューから開き、作成・編集・削除と ↑↓ による番号の入れ替えができる。ファイルの右クリック（複数選択可）→「グループ ▸」で振り分け・解除・新規作成。振り分け済みのファイルはサムネ背景がグループ色になり、右上にグループ名のバッジが出る。ソートに「グループ順」を追加（フォルダ → グループ番号順 → グループなし、グループ内は名前順）。カスタム順と同じくフォルダ単位の並びモードで、ドラッグで並べ替えるとその並びを起点にカスタム順へ移る。
  データは設定ファイルの `folderGroups`（`{ フォルダパス: { groups:[{id,name,color}], files:{ ファイル名: groupId } } }`）に保存し、カスタム順と同じフォルダ単位のタイムスタンプで端末間マージする。グループ番号は配列の位置（1 始まり）。ファイル名・フォルダパスをキーにしているため、名前変更や移動では振り分けが外れる（カスタム順・プリセットと共通の課題として別途対応予定）。
  あわせて、ソート切り替え時に選択状態が別のファイルにずれる不具合を修正（選択はインデックスで持っているため、並べ替え後にファイル単位で付け直す）。

- **Phase 5.1（サムネイル取得キューの分離）**: `.clip` のサムネ生成を専用キュー（`CQ`、同時 3）に移した。Dropbox のサムネ API は 1 リクエストで終わるのに対し `.clip` は Range リクエストを複数回 + パースが走るため、共通キュー（`TQ`、同時 6）を共有すると `.clip` が数個あるだけで全枠を占有し、同じフォルダの画像サムネがその後ろで待たされていた。実測で画像混在フォルダの画像表示が約2倍遅くなっていたのを解消（全体の完了時間は変わらない）。
  あわせて、世代識別子を導入する前のキャッシュキー（`path:content_hash`）にヒットした場合はそれを旧世代として採用するようにした。一覧が `content_hash` を返さない環境で、アップデート直後に全サムネが一旦空になるのを防ぐ。

- **Phase 5（.clip サムネイル + サムネキャッシュ改善）**: CLIP STUDIO PAINT の `.clip` をグリッドでサムネイル表示する。Dropbox の `get_thumbnail_v2` は `.clip` 非対応なので、ファイル内部から自前で取り出す。`.clip` は `CSFCHUNK` コンテナで、`8バイトのチャンク名 + ビッグエンディアン u64 の長さ + データ` が並ぶ構造。その中の `CHNKSQLi` が素の SQLite データベースで、`CanvasPreview` テーブルにキャンバス全体の PNG が入っている。SQLite は依存を増やさないよう最小限の読み取り専用パーサを内蔵（b-tree 走査 + オーバーフローページ連結）。WebAssembly 版 SQLite を使わないのでオフライン動作と単一ファイル構成を維持できる。ダウンロードは `/files/download` の Range リクエストで、ヘッダのオフセットヒント → 末尾 2MB スキャン → チャンク走査 → 広域スキャンの順に安く探す。取り出した PNG は長辺 512px の JPEG に縮小してから保存する。非公開フォーマットなので各段階を検証し、解釈できないファイルは静かにアイコン表示へフォールバックする。
  あわせてサムネキャッシュを改善。キャッシュキーの世代識別子を `content_hash || rev || server_modified` にして、一覧が `content_hash` を返さない場合でも保存のたびに更新されるようにした。新設の `thumbMeta` ストアがパスごとの最新キーを持ち、世代が変わったときは旧サムネを即座に表示してから裏で差し替える（stale-while-revalidate）。差し替え成功時に旧キーを削除するので、頻繁に上書き保存される `.clip` でも IndexedDB が際限なく太らない。IndexedDB は v3。古いタブが残っていてアップグレードがブロックされた場合も `init()` を止めずキャッシュ無効で起動する。

- **Phase 4.5（プロットボード連携・D&D 画像添付）**: サムネイルのラッパー（`.grid-item`）ドラッグ時、ファイルなら `text/plain` に Dropbox 原本パスの JSON（`{v:1, source:'fileviewer', dropboxPath, name}`）を載せて送出。別窓のプロットボードがこのパスを受け取り、自力でダウンロード→縮小→添付する（File 実体はブラウザ制約で別窓へ渡せないため文字列で受け渡す）。サムネ `<img>` は `draggable="false"`（既定の画像ドラッグが自前ペイロードに混ざるのを防ぐ）。`effectAllowed` は内部移動の `move` と外部窓への `copy` を両立させる `copyMove`。内部の移動・並べ替え D&D 挙動は従来どおり（`dragSrcIdx` で処理し `text/plain` は読まない）。PC の 2 窓運用向け。
